- (constraint) El usuario necesita editar contenido (precios, video hero, textos de paquetes) sin tocar código. Solución CMS debe ser mínima — no un CMS completo.
- (decision) CMS: Decap CMS (open source, gratuito). Panel admin en /admin. Contenido editable (precios, video URL, textos paquetes) almacenado en archivos YAML/JSON en Git. Binds: toda edicion de contenido pasa por Decap. Prevents: edicion directa de código por el usuario del negocio.
- (decision) Framework: Astro. Renderizado estatico por defecto (SSG), adapter @astrojs/cloudflare para rutas server-side (API endpoints del formulario). Binds: todos los componentes UI son Astro components o islands. Prevents: usar React/Vue/Svelte como framework principal.
- (decision) Hosting: Cloudflare Pages + Cloudflare Workers. Deploy automatico desde GitHub. CDN global — critico para carga rapida desde Miami/Madrid a Lima. Binds: toda funcion server-side es un Cloudflare Worker o un Astro API route via adapter Cloudflare.
- (decision) Base de datos: Supabase (PostgreSQL). Almacena leads del formulario de contacto y suscripciones de email. Las keys de Supabase (service role) viven SOLO en variables de entorno de Cloudflare Workers — nunca expuestas al cliente.
- (constraint) Decap CMS en Cloudflare Pages requiere un Cloudflare Worker para manejar el OAuth callback de GitHub (no tiene Git Gateway integrado como Netlify). El freelancer debe implementar este Worker de autenticacion.
- (decision) Flujo de leads: formulario → Cloudflare Worker (API route de Astro) → INSERT en Supabase. Sin notificaciones externas. Los leads se consultan directamente desde el dashboard de Supabase. Binds: no se necesita UI de admin custom para ver leads. Prevents: dependencia de servicios de email/notificacion en v1.
- (decision) Supabase: proyecto nuevo exclusivo para presencia-web (separado del proyecto zboxdsiejvmjupdawgax que pertenece a otro producto). Tablas iniciales: 'leads' (nombre, whatsapp, ciudad, fecha, paquete, created_at) y 'subscriptions' (email, created_at). RLS activo, acceso solo via service role key en Cloudflare Worker env vars.
- (decision) i18n: rutas separadas por idioma usando Astro i18n nativo. /es/ (default) y /en/. Contenido de ambos idiomas gestionado via Decap CMS. hreflang tags para SEO. Binds: toda pagina tiene contraparte en el otro idioma. Prevents: implementacion de toggle JS sin rutas reales.
- (decision) Analytics: Cloudflare Web Analytics (sin cookies, GDPR-compliant) + evento JS personalizado al click en cualquier enlace de WhatsApp. El evento reporta tasa de conversion real. Binds: todos los enlaces WhatsApp del sitio deben disparar el mismo evento 'whatsapp_click'. Prevents: implementar Google Analytics (innecesario dado Cloudflare ya disponible).
- (decision) Video Hero: archivo de video alojado en el repositorio Git (/public/videos/hero.mp4). Cloudflare Pages lo sirve via CDN automaticamente. Para swappearlo: el usuario sube el nuevo archivo via Decap CMS media library (commit automatico al repo → redeploy). Binds: video referenciado por ruta relativa fija, no URL externa. Prevents: dependencia de YouTube/Vimeo/R2 para el hero video.
